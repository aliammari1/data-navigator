## Design tokens

There are **three coexisting token systems**:

1. **shadcn oklch tokens** — `src/app/globals.css`: light `:root` (23–61) + `.dark` (63–100); `--background/--card/--primary/...`, plus non-standard extensions `--success`/`--warning`, `--chart-1..5`, full `--sidebar-*` group, `--radius: 0.75rem` with a derived sm→4xl radius scale (142–148). Tabular-nums utility for `.metric-value/.kpi-number/[data-numeric]` (173–181), thin scrollbar, landing keyframes, `prefers-reduced-motion` guard.
2. **"Atlas Design System"** — `src/design/tokens.css` (imported in layout.tsx:9): a *second* full token vocabulary (`--atlas-bg #070b14`, `--atlas-accent` = radix blue-9, 4-pt spacing grid, 5 shadow elevations, glow tokens, motion durations with a `--motion-allowed` kill-switch, density scaling). Keyed on `[data-theme="light|dark"]` — a **different theme mechanism** than the app's `.dark` class. Consumed only by `src/design/primitives|blocks`, which are imported by just **4 files** (analytics-theater ×3, forecast-intelligence ×1).
3. **Settings-driven runtime overrides** — `src/features/settings/components/settings-effects.tsx` writes `--primary/--ring/--sidebar-primary/--radius/--dn-space` inline on `<html>` and bridges to `applySettings()` (`--accent`, `--density-scale`, `--motion-allowed`, `data-accent/density/animations`).

**Critical: the `dn-*` classes are defined nowhere.** `dn-page`, `dn-page-shell`, `dn-page-shell-wide`, `dn-sticky-header`, `dn-panel`, `dn-app-bg` are used in **16 files** (e.g. DashboardHomeScreen.tsx:223–224,315,347; dashboard-layout.tsx:48; SettingsScreen.tsx:118,200; HelpScreen.tsx:27–28; ParsedDataScreen.tsx:80,290,390; DataBrowserScreen.tsx:1087,1096; AiAnalysisScreen.tsx:471–472) but the repo's only two CSS files (globals.css, tokens.css) contain no definition, no `@utility`, no `@layer components`, no styled-jsx injection. Whatever page-shell padding/max-width/sticky-header treatment these names were meant to provide is a **silent no-op** — e.g. `HelpScreen.tsx:28` `"dn-page-shell max-w-4xl space-y-8"` has no `mx-auto` or padding of its own, so the shell class was clearly expected to supply centering/gutters.

## Theme & palette

- **Dark-first**: `dark` hardcoded on `<html>` (layout.tsx:52), `defaultTheme="dark"`; viewport themeColor `#07090f`.
- **Custom ThemeProvider** (`src/components/theme-provider.tsx`) — a hand-rolled next-themes clone (localStorage `"theme"`, class attribute, system listener). `next-themes` is in dependencies but its only import is `src/components/ui/sonner.tsx:3` — which calls next-themes' `useTheme()` **with no next-themes provider in the tree**, so toasts always resolve `theme = "system"` (OS theme), diverging from the app theme.
- **Intended palette** (dark): deep navy background `oklch(0.145 0.012 265)`, card `oklch(0.185 0.014 263)`, **electric-cyan primary `oklch(0.789 0.154 211)`**, 10%-white borders, mint success / amber warning, cyan/blue/mint/amber/violet chart ramp. globals.css:17–21 explicitly claims "a single electric-cyan accent".
- **Actual accent usage is fragmented**: hardcoded **teal** in the sidebar (app-sidebar.tsx:69–70 `bg-teal-500/15 ... text-teal-400`, :146 `text-teal-500/60`, :164 `border-teal-400 bg-teal-400/8 text-teal-300`; nav-button.tsx:38,45) and telecom screens (DashboardHomeScreen.tsx:227 `from-teal-700 to-emerald-600`, :295 `bg-teal-700`); **blue** for the topbar AI button (topbar.tsx:164 `bg-blue-500/10 text-blue-400`); **indigo** for selection states (telecom kpi-card.tsx:66,81; overview-tab.tsx:145); **violet** gradients in AI Briefing (AIBriefingScreen.tsx:60); **cyan** on landing/auth. The settings accent picker only rewrites `--primary`/`--ring`, so none of these hardcoded hues follow it.
- **Atlas/light mismatch**: ThemeProvider toggles a *class*; Atlas tokens key on `[data-theme]`, which ThemeProvider never sets — Atlas-styled surfaces (analytics-theater, forecast panel) stay dark in light mode.

## Landing page assessment

`src/app/page.tsx` (816 lines, plus `src/components/landing/interactive.tsx` and `visuals.tsx`). This is the most polished surface in the app:

- Fixed nav with scroll-state border/blur (`useMotionValueEvent`, line 197), mobile Sheet menu (a mobile nav the dashboard itself lacks).
- Hero with **3D mouse-tilt dashboard mock** (`useMotionValue` + `useTransform` rotateX/rotateY, lines 290–313) containing real mini-charts, animated underline on the headline, `min-h-[100dvh]`.
- Count-up telemetry band (react-countup with scroll-spy), bento capabilities grid with **SpotlightCard** cursor-following radial highlight (interactive.tsx:11–44), architecture pillars + `flow-shimmer` animated pipeline, three-tier pricing with highlighted card, FAQ accordion, CTA band.
- Atmosphere: dual `aurora` radial blobs (`aurora-pan` 20s keyframes), fixed SVG `bg-noise` grain at 2.5% opacity; `useReducedMotion` respected throughout, plus the globals.css media query.
- **Weaknesses**: completely detached from the token system — hardcoded `bg-[#07090f]`, `text-[#04121f]`, `cyan-300/400`, `white/10` everywhere, so the landing's cyan brand does not match the dashboard's teal chrome; SaaS-template pricing ("SSO", "SLA", "Talk to us") is incongruent for an offline-first desktop app; scroll choreography is limited to repeated `whileInView` fade-ups (the `Reveal` wrapper) — no parallax, pinning, or scroll-scrubbing; every section uses the identical `max-w-7xl px-6 py-28` rhythm.

## Top 10 visual problems ranked (with evidence)

1. **Undefined `dn-*` layout classes across 16 screens** — `dn-page`, `dn-page-shell(-wide)`, `dn-sticky-header`, `dn-panel`, `dn-app-bg` (dashboard-layout.tsx:48, DashboardHomeScreen.tsx:223–224, SettingsScreen.tsx:118/200, ParsedDataScreen.tsx:80, etc.) exist in no CSS file in the repo. Page gutters, max-widths, sticky headers and panel surfaces these names promise are silent no-ops; screens like HelpScreen.tsx:28 (`dn-page-shell max-w-4xl` with no mx-auto/padding) are visually broken as a result.
2. **Appearance settings only work on the Settings page** — `SettingsEffects` is mounted solely inside `SettingsScreen.tsx:120`, and its unmount cleanup (settings-effects.tsx:164–169) strips `--primary/--ring/--radius/--dn-space`; navigating away reverts the user's accent/density everywhere.
3. **Three competing design systems with mismatched theme mechanisms** — shadcn oklch tokens (`.dark` class), Atlas `--atlas-*` (`[data-theme]` attribute the ThemeProvider never sets → Atlas surfaces stuck dark in light mode), and the hardcoded landing palette; plus a dead v3 `tailwind.config.ts` whose `hsl(var(--…))` wrappers contradict the oklch variables.
4. **No mobile navigation at all** — sidebar is `hidden md:flex` (app-sidebar.tsx:60) with no drawer fallback, and topbar controls are `hidden sm:flex` (topbar.tsx:153,164,174); below `md` the dashboard has no way to navigate, while the marketing page ships a Sheet-based mobile menu.
5. **Hardcoded dark colors break light theming** — DeepAnalyticsScreen.tsx:699/708/737 (`bg-slate-900`, `text-slate-100`), report-studio gradient cards (:50–54), landing-only hexes; the complete light token set in globals.css:23–61 is undermined wherever screens bypass it.
6. **Accent fragmentation: teal vs cyan vs blue vs indigo vs violet** — globals.css:19 claims "a single electric-cyan accent", but the sidebar is teal (app-sidebar.tsx:69,164), the AI button blue (topbar.tsx:164), selection states indigo (kpi-card.tsx:66), AI surfaces violet (AIBriefingScreen.tsx:60), landing cyan. No single brand hue survives across surfaces, and none track the settings accent picker.
7. **Typography chaos** — page h1 sizes range from `text-sm` (DashboardHomeScreen.tsx:232) to `text-3xl` (page-header.tsx:47); **857 occurrences of sub-12px text (`text-[9px]/[10px]/[11px]`) across 150 files**, including 9px nav section labels (app-sidebar.tsx:107) — below comfortable readability/accessibility floors and applied inconsistently.
8. **Shared primitives are dead on arrival while clones proliferate** — PageHeader used once (shell-overview-screen.tsx:87), StatsCard never used in production, `ui/sidebar.tsx` imported by zero files, Atlas primitives used by 4 files; meanwhile telecom `KPICard`, telecom `Section`, report-studio `TemplateCard` and 16 ad-hoc page headers duplicate them. Two identical `cn()` utils (src/lib/utils.ts vs src/shared/utils.ts) split the import graph.
9. **Toast theming is broken by a provider mismatch** — `ui/sonner.tsx:3` imports `useTheme` from `next-themes`, but the app uses a custom ThemeProvider; with no next-themes provider, toasts always fall back to `"system"` and can render light toasts in a dark app (and vice versa).
10. **Redundant/conflicting visual dependencies degrade consistency** — five chart libraries (echarts/recharts/uplot/vega/force-graph) with `--chart-1..5` tokens only wired to the near-unused recharts path; two variant systems (cva + tailwind-variants); two confetti libraries; two tour libraries (driver.js + react-joyride); two headless UI kits (radix-ui + @base-ui/react). Each pair is a fork in visual behavior and bundle weight.
