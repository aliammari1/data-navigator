# data-navigator — Feature Improvement Roadmap

_Generated by a 28-agent claude-flow/Workflow swarm (per-feature code review + 2025-2026 web research)._

## Executive Summary

data-navigator is an ambitious, local-first (Next.js 16 / React 19 + Electron) in-browser data analytics platform built on a genuinely strong technical foundation: DuckDB-wasm for in-browser SQL, a full local-AI stack (@mlc-ai/web-llm, @huggingface/transformers, sherpa-onnx TTS), TanStack Query/Zustand for state, and rich charting (ECharts, Vega-Lite, react-force-graph, Leaflet). Roughly 27 feature surfaces span data ingestion, profiling, transformation, visualization, forecasting, lineage, reconciliation, collaboration, reporting, and AI narrative generation.

The single dominant theme across the portfolio is a credibility/grounding gap: a large majority of the "intelligence" features (ai-analysis, ai-briefing, analytics-theater, channel-monitor, deep-analytics, geo-analysis, forecast-intelligence, report-studio, reconciliation, collab/collaboration, data-formulator) run on hardcoded constants or Math.random() mock data and are disconnected from the very DuckDB/data-store/LLM infrastructure the app already ships. Many present fabricated confidence scores, fake p-values, and synthetic charts, making "AI Analysis," "Deep Analytics," and "real-time monitoring" features demos rather than tools. A second theme is unused-but-installed capability: Vega-Lite, yjs/y-websocket, cmdk, react-resizable-panels, @dnd-kit, react-virtual, fuse.js, exceljs, arquero, and the local LLM provider stack are all dependencies that key features fail to use, so closing many gaps requires wiring rather than adding. A third theme is monolithic 1,000-3,000-line "use client" screens with near-zero test coverage and several real correctness/security defects (SQL injection in data-browser and data-transform via non-global quote escaping and raw numeric interpolation, exponential-blowup graph traversal in lineage, divergent persistence/data paths). A fourth theme is performance/scale: most heavy stats and parsing run on the main thread over LIMIT samples instead of pushing single-pass SUMMARIZE/window-function work into DuckDB or Web Workers.

The biggest opportunity is to make the app honest and trustworthy by grounding every analytical surface in real DuckDB query results and the existing LLM stack, fix the security/correctness defects on hot paths, then activate the already-installed libraries (Vega-Lite, Yjs, cmdk, react-virtual, exceljs) to deliver collaboration, performant grids, structured exports, and real onboarding with minimal new dependencies.

## Quick Wins

- data-browser: Fix the SQL escaping/injection bug in model/helpers.ts (use replaceAll in quoteIdentifier/quoteLiteral and stop raw-interpolating numeric/between/in operator values) — a correctness AND security defect on the hottest path (effort S, impact high).
- lineage: Index nodes in a Map<id,LNode> and add shared visited-sets + cycle guards to walkUp/walkDown/walkImpact; stop calling nodes.find() inside render/BFS loops — removes a real hang/exponential-blowup risk on diamond/cyclic graphs (effort S, impact high).
- agent-canvas: Wire live per-node status by projecting AG-UI STEP/INTERRUPT events onto flowNodes via the already-defined updateFlowNode and fix the empty-dependency memos — smallest change that makes the centerpiece graph actually live (effort S, impact high).
- history: Add Copy SQL and Re-run/Open-in-editor actions to query-history rows (SQL already stored in QueryHistoryItem) — converts a read-only log into the core workflow users expect (effort M-low, impact high).
- history: Swap the substring filter for the already-installed fuse.js fuzzy search built in useMemo over aggregated rows (effort S, impact high).
- settings: Make appearance settings actually apply by setting data-density and an --accent CSS var on <html> and unifying store.theme with theme-provider — turns a dead first-shown tab into a working one (effort M-low, impact high).
- help / ux-innovations: Mount the already-built react-joyride OnboardingTour in the dashboard layout and add a 'Restart tour' button — ships the headline onboarding value in one small change (effort S, impact high).
- data-transform: Centralize safe SQL generation (global quoteIdent/quoteLit) and fix the funnel/Reduction analytics that hardcode a 10,000-row baseline instead of sourceRowCount (effort S each, impact medium-high).
- data-transform: Wire up the already-installed @dnd-kit/sortable for real drag-and-drop step reordering (GripVertical already imported) (effort S, impact medium).
- geo-analysis: Replace Math.random() network/heatmap generators with deterministic seeded (or query-derived) data so views are reproducible (effort S, impact high).
- parsed-data / data-browser: Replace bespoke per-column stats with a single DuckDB SUMMARIZE pass plus approx_count_distinct/approx_quantile — fewer scans, exact results, less code, pattern already used in tool-registry.ts (effort S-M, impact high).
- forecast-intelligence: Add a fan chart (nested 50/80/95% bands) with a forecast-start marker once empirical quantiles exist — nearly free in the ECharts option builder (effort S, impact medium).
- deep-analytics: Surface the already-built but orphaned ReconciliationWizard as a tab and add IQR-based outlier detection reusing existing p25/p75 (effort S, impact medium).
- settings: Add JSON import/export and reset-with-confirm leveraging the exportable drizzle storage row (effort S, impact medium).
- data-browser: Use DuckDB USING SAMPLE (reservoir) for instant previews/type inference and debounce filter/search input via use-debounce (effort S, impact medium).

## Top Cross-Cutting Initiatives

### Ground every analytical feature in real DuckDB data instead of mock/hardcoded constants  _(high)_

The most pervasive and damaging gap: a majority of intelligence features run on Math.random() or hardcoded literals (SAMPLE_DATA, TUNISIA_REGIONS, seededRand), so they analyze nothing the user loaded. The app already exposes a DuckDB-wasm query layer (src/core/queries/duckdb.ts, runReadOnlyQuery, useDuckDBQuery), TanStack Query, and Zustand data stores. Wiring screens to real datasets with column/dataset pickers is the prerequisite that makes every downstream improvement (real stats, forecasts, exports, hypotheses) actually valuable, and converts demos into trustworthy tools.

Features: ai-analysis, ai-briefing, analytics-theater, channel-monitor, deep-analytics, geo-analysis, forecast-intelligence, report-studio, reconciliation, data-formulator, agent-canvas

### Activate the existing local-AI stack for grounded, structured, streaming insight generation  _(high)_

Multiple features fabricate insights with hardcoded confidence (0.87/0.93) or fake p-values while ignoring the shipped provider stack (platform/ai/insights.ts, web-llm, transformers.js). Feed pre-computed DuckDB stats into the LLM for grounded narratives, adopt constrained/JSON-schema decoding (web-llm response_format, structured.ts) to replace fragile regex+JSON.parse, add token streaming for perceived latency, and emit evidence-linked claims to reduce hallucination. This makes the app's headline 'AI' promise real and consistent across features.

Features: ai-analysis, ai-briefing, data-formulator, agent-canvas, deep-analytics, reconciliation, telecom, data-transform

### Fix correctness and security defects on hot paths, then add regression tests  _(high)_

There are real defects: SQL injection / broken escaping in data-browser (quoteIdentifier/quoteLiteral replace only the first quote; numeric operators interpolate raw input) and data-transform (same non-global escape), exponential-blowup/no-cycle-guard graph traversal in lineage that can hang the UI, duplicated/divergent audit and data paths in collab-hub and history. Per the repo's own anti-slop working agreement, these should be locked behind regression tests before the larger refactors. Centralized safe SQL generation + parameterized runReadOnlyQuery also unblocks server-side filtering and infinite scroll.

Features: data-browser, data-transform, lineage, collab-hub, history

### Push statistics, profiling, and anomaly detection into DuckDB SQL and off the main thread  _(high)_

Features compute stats in JS over 2,000-3,000 row LIMIT samples (inaccurate, silently truncated) or fire 2-4 queries per column. Replacing per-column loops with single-pass DuckDB SUMMARIZE, approx_count_distinct/approx_quantile, CORR, and windowed z-scores yields exact results in milliseconds with far less code. Moving heavy parsing/transform/profiling into Web Workers (the app already ships workers for VAD) keeps the UI responsive. This is both a correctness and a performance unlock.

Features: ai-analysis, parsed-data, data-transform, deep-analytics, channel-monitor, telecom, data-browser

### Make collaboration real with the already-installed Yjs CRDT stack  _(high)_

yjs and y-websocket are in package.json but never imported; the collaboration screen is single-user local state with empty seed arrays, and collab-hub uses BroadcastChannel (same-browser only). Migrating shared state (presence, annotations, approvals, audit, comments, chat) to a Y.Doc with Awareness for presence, y-indexeddb for offline persistence, and y-webrtc/y-websocket transport (keyed by the existing sessionCode/dataset) turns simulations into genuine cross-device, conflict-free collaboration fitting the backendless local-first model. Yjs also fixes agent-canvas layout persistence.

Features: collaboration, collab-hub, agent-canvas

### Modernize visualization and grids with installed-but-unused libraries (Vega-Lite, react-virtual, react-arborist, React Flow)  _(high)_

Vega-Lite/react-vega are installed but charts go through a bespoke ECharts builder (data-formulator), grids cap at 500 non-virtualized rows or window only the current page (data-browser, csv-parser), folders hand-rolls an O(n^2) tree, and lineage reimplements pan/zoom instead of using React Flow/dagre. Adopting headless TanStack Table + react-virtual for windowed infinite scroll, react-arborist for the catalog tree, @xyflow/react+dagre for lineage, and Vega-Lite for declarative LLM-emitted specs deletes large bespoke code and scales to millions of rows.

Features: data-formulator, data-browser, csv-parser, folders, lineage, history, channel-monitor

### Complete the multi-format export and reporting pipeline  _(medium)_

report-studio ships PPTX/DOCX/PDF generators but on SAMPLE_DATA, has no .xlsx despite exceljs being intended, and DOCX charts are text placeholders. Several features have JSON-only or no export. Wiring exports to real query results, embedding rendered ECharts PNGs (getDataURL) into PDF/PPTX, adding ExcelJS, streaming full-result exports via DuckDB COPY (not just the current page), and honoring branding (logo/color) turns reporting into a real shareable deliverable across the product.

Features: report-studio, ai-analysis, ai-briefing, data-browser, reconciliation, deep-analytics, analytics-theater

### Ship onboarding, command-palette, and customizable-shell UX  _(medium)_

The react-joyride OnboardingTour and AchievementSystem are dead code imported nowhere; the dashboard home route redirects away and is telecom-locked; cmdk/react-resizable-panels are installed but the command palette is hand-rolled and navigation-only; appearance settings (accent/density) are written but never applied. Mounting the tour, building a dataset-agnostic home with recent datasets/queries/saved charts, making Cmd+K action-oriented via cmdk, applying appearance settings as CSS variables, adding an Account/Security section via the configured better-auth, and persisting layout deliver high-visibility activation and usability wins.

Features: help, ux-innovations, dashboard-shell, dashboard-home, settings, folders

## Roadmap

# data-navigator — Consolidated Improvement Roadmap

## Context & Guiding Principles

data-navigator is a local-first (Next.js 16 / React 19 + Electron) in-browser analytics platform with a strong foundation (DuckDB-wasm, local LLMs via web-llm/transformers.js, sherpa-onnx TTS, TanStack Query/Zustand, ECharts/Vega-Lite). The dominant problem across ~27 features is that most "intelligence" surfaces run on **mock/hardcoded data** and ignore infrastructure the app already ships. A second problem is **installed-but-unused dependencies** (Vega-Lite, Yjs, cmdk, react-virtual, exceljs, @dnd-kit, fuse.js, the LLM provider stack). A third is **monolithic untested screens** with several **real security/correctness defects**.

Execution principles (aligned with the repo's anti-slop working agreement):
- Prefer wiring existing infra/dependencies over adding new ones.
- Lock behavior with regression tests before refactoring monoliths.
- Fix security/correctness defects first; they sit on hot paths and block downstream work.
- Push heavy compute into DuckDB SQL / Web Workers, not JS over LIMIT samples.

---

## Phase 1 — Trust, Safety & Foundations (Weeks 1-6)

**Goal:** Make the app honest and safe. Fix defects, ground the worst offenders in real data, and lay the SQL/test foundation everything else builds on.

### 1.1 Fix security & correctness defects (effort S-M, impact high)
- **data-browser:** In `model/helpers.ts`, `quoteIdentifier`/`quoteLiteral` use `String.replace` with a string arg (escapes only the first quote); numeric operators (`gt/gte/lt/lte/between/in`) interpolate `r.value` with **no escaping**. Switch to `replaceAll` and extend `runReadOnlyQuery` to accept bind values so DuckDB-wasm prepared statements (`?`/`$` placeholders) escape and type filter values. *(https://duckdb.org/docs/current/clients/c/prepared, https://github.com/duckdb/duckdb-wasm/issues/117)*
- **data-transform:** Same non-global escape in `stepToSQL()`; add `quoteIdent()`/`quoteLit()` helpers, restrict structural fields to validated identifiers from the profiled schema, keep raw SQL only in explicit advanced fields. Stop littering `step_<id>` write tables without cleanup.
- **lineage:** Build a `Map<id,LNode>`, add shared visited-sets and cycle guards to `walkUp`/`walkDown`/`walkImpact`, and remove `nodes.find()` from render/BFS loops — fixes exponential blowup / hang on diamond/cyclic graphs. *(https://reactflow.dev/learn/advanced-use/performance)*

### 1.2 Centralize a safe, parameterized DuckDB query path (effort M, impact high)
- Extend `runReadOnlyQuery` with a bind path; route all feature filters through it. This unblocks server-side search and infinite scroll (Phase 2).

### 1.3 Ground the highest-leverage mock features in real DuckDB data (effort L, impact high)
Wire screens to `src/core/queries/duckdb.ts` (`runReadOnlyQuery`/`useDuckDBQuery`), the data-store, and TanStack Query, with dataset/column pickers:
- **ai-analysis:** Replace static string-template insights + fabricated confidence (0.87/0.93/0.78) by feeding real DuckDB column stats/correlations/anomalies into the existing `platform/ai/insights.ts` provider stack. *(https://aclanthology.org/2025.naacl-long.24/, https://mantelgroup.com.au/dashboards-natual-language-insights)*
- **ai-briefing:** Replace `SAMPLE_DATA` with real data-store/DuckDB aggregates (reuse `insights.ts`/`report-ai.ts`); grounding is the biggest hallucination reducer. *(https://www.factored.ai/engineering-blog/llm-hallucination-evaluation)*
- **channel-monitor:** Replace `seededRand` PRNG with polling/incremental SQL aggregation over real tables.
- **deep-analytics:** Connect all four tabs to real datasets with a picker (prerequisite for real stats below). *(https://motherduck.com/learn/product-analytics-motherduck-duckdb/)*
- **geo-analysis:** Wire the map to DuckDB with a lat/lon/metric/category column-mapping UI and kill `Math.random()` generators. *(https://duckdb.org/2025/08/08/spatial-joins)*
- **forecast-intelligence:** Route `ForecastScreen.tsx` through the existing strong `forecast-engine` over real data instead of `generateHistoricalData()`/weak `linearForecast()`.
- **report-studio:** Point generators at real query results instead of `SAMPLE_DATA`.
- **reconciliation:** Replace the two literal arrays with a DuckDB `FULL OUTER JOIN` + row-hash + variance diff engine via the existing query layer. *(https://sekuel.com/learn-sql/duckdb-cookbook/compare-tables-in-duckdb/)*
- **analytics-theater / agent-canvas / data-formulator:** Begin replacing module-load `Math.random()`/`SELECT * LIMIT 2000` with query-driven aggregates (full migration continues in Phase 2).

### 1.4 Quick wins that ship value immediately (effort S, impact high/medium)
- **agent-canvas:** Project AG-UI STEP/INTERRUPT events onto `flowNodes` via `updateFlowNode`; fix empty-dependency memos so the graph goes live. *(https://docs.langchain.com/oss/javascript/langgraph/interrupts)*
- **history:** Add Copy SQL + Re-run/Open-in-editor (SQL already in `QueryHistoryItem`); swap substring filter for installed **fuse.js**. *(https://www.fusejs.io/articles/using-fuse-with-react.html)*
- **settings:** Apply appearance settings (`data-density` + `--accent` CSS var on `<html>`) and unify `store.theme` with `theme-provider`.
- **help / ux-innovations:** Mount the already-built `OnboardingTour` and add a "Restart tour" button.
- **data-transform:** Fix funnel/Reduction analytics that hardcode a 10,000-row baseline instead of `sourceRowCount`; wire installed **@dnd-kit/sortable** for step reordering.

### 1.5 Lock pure logic behind tests (effort M, impact medium)
Add Vitest coverage for the pure analytics/parsing cores before larger refactors: `telecom` insights/forecast/anomaly math, `csv-parser` detectType/castValue/applyFilter, `ai-briefing` parsing/z-score, `reconciliation` diff/variance, `parsed-data` profiling.

## Phase 2 — Compute, Scale & Visualization (Weeks 6-14)

**Goal:** Make analytics correct and fast at scale; activate installed-but-unused viz/grid/graph libraries; complete the AI layer.

### 2.1 Push statistics & profiling into DuckDB; move heavy work off the main thread (effort M-L, impact high)
- **parsed-data / data-browser:** Replace per-column query loops with a single **DuckDB SUMMARIZE** pass + `approx_count_distinct`/`approx_quantile`/`reservoir_quantile`; gate exact vs approximate by row count. *(https://duckdb.org/docs/current/guides/meta/summarize, https://database.guide/approx_quantile-examples-in-duckdb/)*
- **ai-analysis:** Push STDDEV/CORR/QUANTILE_CONT/SKEWNESS/KURTOSIS/REGR_* and SUMMARIZE over the **full dataset** instead of JS over 2-3k-row samples. *(https://motherduck.com/blog/duckdb-wasm-in-browser/)*
- **deep-analytics:** Replace fabricated p-values with **jstat** Welch's t-test/CIs/effect sizes; make Revenue Attribution a real `ml-matrix` multiple regression (optionally exact Shapley); standardize cluster features, add elbow+silhouette and a density-based option; reframe cohorts as a true retention triangle via window functions. *(https://github.com/jstat/jstat, https://christophm.github.io/interpretable-ml-book/shapley.html)*
- **channel-monitor / telecom:** Replace static thresholds + `Math.random()` gating with **EWMA/MAD/z-score** adaptive anomaly detection computed in DuckDB window functions; add Seasonal-Hybrid ESD / STL decomposition for seasonal data. *(https://www.scitepress.org/Papers/2025/134378/134378.pdf, https://arxiv.org/pdf/2008.09245)*
- **Web Workers:** Move parsing (csv-parser papaparse `worker:true` + step/chunk), transform execution, ai-analysis pipeline, and report generation off the main thread. *(https://www.papaparse.com/, https://motherduck.com/blog/duckdb-wasm-in-browser/)*
