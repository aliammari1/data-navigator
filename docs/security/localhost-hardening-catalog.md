**Intentional http-loopback choices (single note, not numbered practices):** no `upgrade-insecure-requests` (app is intentionally `http://localhost`); no cookie `Secure` flag (Secure cookies are dropped over plain http even on loopback — rely on cookie encryption at rest + HttpOnly + SameSite); no TLS on the embedded server. ## B. IPC & Preload Architecture

17. **Never expose raw `ipcRenderer` (or generic `send`/`invoke`/`on`) over contextBridge** — that turns the bridge into an arbitrary-IPC primitive and defeats channel allowlisting. The six bridges (`electronFS/DuckDB/Voice/Llama/Models/Collab`) are method-per-channel. Never add an `invoke:(channel,...args)=>…` escape hatch. **[DONE]** — Source: https://www.electronjs.org/docs/latest/tutorial/context-isolation#security-considerations
18. **Wrap event callbacks so `IpcRendererEvent` (and `event.sender`) never leak** — `onToken`/`onProgress`/`onDiscovered` use `(_event, payload) => callback(payload.…)`, drop `_event`, and filter by request id so one subscriber can't read another's stream. Keep for every future subscribe API. **[DONE]**
19. **One narrow method per IPC message** — least-privilege API surface; each exposed function is the unit of capability. **[DONE]**
20. **Validate the sender of EVERY IPC message** [main.ts:133-149] — every `ipcMain.handle` is wrapped in `withTrustedSender` → `assertTrustedSender`, parsing `event.senderFrame?.url` with a real URL parser against `isAllowedAppOrigin` (never `startsWith`/`indexOf`). **[DONE]** — Source: https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages
21. **Route every handler through one `registerHandler(channel, schema, fn)` factory** (merges sender-check + central registration + per-channel Zod parse). The factory applies `withTrustedSender` + a `.strict()` Zod schema parse + try/catch, eliminating the "forgot to validate" class. **Runtime payload validation is the critical part:** TS `Window` declarations erase at runtime, so a same-origin XSS'd renderer can send malformed/oversized/prototype-polluting payloads. Today only `filePath`/`targetPath` are string-checked, then `...(input as Record<string,unknown>)` is spread untyped into services (`delimiter`, `sampleSize`, `maxTokens`, `jsonSchema`, `temperature`, where/sort/cursor reach DuckDB/llama unchecked). Bound numerics with `.min/.max`, constrain enums, reject unknown keys. Then a CI grep fails if a bare `ipcMain.handle(` appears outside the factory (Electron has no built-in central IPC hook — issue #33517). Zod is already a dependency. **[TODO — CRITICAL]** — Source: https://github.com/electron/electron/issues/33517
22. **Treat free-form SQL over IPC as a privileged sink** — `duckdb:runReadOnlyQuery`/`runReadOnlyQueryArrow` accept arbitrary SQL; even "read-only" SQL exfiltrates via `read_csv`/`read_parquet`/`glob`/`INSTALL`/`LOAD`/`ATTACH`/`COPY ... TO`, turning a query channel into arbitrary local file read/write. Open the renderer-facing DuckDB connection genuinely read-only with `enable_external_access=false` and file functions disabled; prefer the structured endpoints (`previewDataset`/`profileDataset`/`fetchKeysetPage`/`countRows`) and consider removing the raw-SQL channel; if kept, reject non-SELECT and block `INSTALL/LOAD/ATTACH/COPY/PRAGMA`. **[TODO — HIGH]** — Source: https://duckdb.org/docs/operations_manual/securing_duckdb/overview.html
23. **Capability-scoped APIs: keys/handles, not raw paths/URLs** — `models:download` takes an allowlisted `key` (not a URL); datasets referenced by `datasetId`. Keep new resources from accepting attacker-forgeable absolute paths/URLs; resolve server-side. **[DONE — keep extending]**
24. **Validate paths in main even for dialog-sourced inputs** [security.ts `PathAccessController`] — `assertAllowedReadPath/WritePath/DeletePath/DirectoryPath` resolve and require containment in `DATA_DIR` or the dialog-remembered allowlist; deletes restricted to `DATA_DIR`. **Hardening remaining:** reject symlinks escaping `DATA_DIR` (realpath check) and Windows reserved/UNC paths explicitly; cover traversal/UNC/symlink-escape in tests. (TOCTOU race is item 62.) **[DONE]** + symlink/UNC tests **[TODO]**
25. **Guard the main→renderer push side** — `llama:token`/`models:progress`/`collab:discovered` check `!event.sender.isDestroyed()` and prefer `event.sender` (the invoker) over a global window for request-scoped streams. Never broadcast sensitive data to all windows. **[DONE]**

Map service internals to explicit DTOs so absolute `cachePath`/`sourcePath`/connection counts don't leak (audit `DuckDBStatus.dbPath/datasetsDir`); catch errors in main and rethrow sanitized messages so stacks/internal paths don't cross. ## F. Embedded Localhost Server (Next.js standalone :3000)

45. **Assert loopback (127.0.0.1) bind; treat `0.0.0.0` as forbidden (merges positive + negative).** [startNextJSServer, main.ts:790-872] hostname is derived from `BETTER_AUTH_BASE_URL`. Before `startServer`, assert the resolved bind is loopback and **throw otherwise** — never rely on the `'localhost'` string (it can resolve `::1`-only and cause a renderer/server IPv6 mismatch; prefer numeric `127.0.0.1`). A `0.0.0.0` bind would expose the full app (DuckDB data, auth) to the LAN; on macOS/Linux a `0.0.0.0` listener is reachable from a public website ("0.0.0.0 Day"). **[APPLYING-NOW — HIGH]** — Source: https://www.electronjs.org/docs/latest/tutorial/security , https://www.oligo.security/blog/0-0-0-0-day-exploiting-localhost-apis-from-the-browser
46. **Add `src/middleware.ts` = the localhost HTTP self-defense layer (merges Host-allowlist + Sec-Fetch CSRF + Origin fallback + capability token + CORS preflight-deny).** No `src/middleware.ts` exists today; better-auth protects only `/api/auth/*`, so every other route is exposed to any visited site or local process that guesses :3000. Implement one middleware that does all of:
    - **Host-header allowlist (DNS-rebinding defense):** strip port/brackets, lowercase, allow only `localhost`/IP-literals/`127.0.0.1`/`::1`. *Next 16 middleware may miss some static assets in standalone mode — prefer wrapping the underlying `http.Server` request listener (or reuse Vite's extracted `host-validation-middleware`).*
    - **Sec-Fetch-Site CSRF:** reject non-safe methods (POST/PUT/PATCH/DELETE) when `Sec-Fetch-Site` is present and not `same-origin`/`none` (Sec-Fetch is sent to localhost, no HTTPS needed).
